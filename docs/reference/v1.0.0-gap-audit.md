> Produced by a dedicated read-only audit agent (Opus) after the WO-069 Phase-1 design workflow's own
> gap-audit input came back a stub. This is the audit of record; the regime design's §5 defers to it.

**Scope reviewed:** CHANGELOG, WO-069 + regime-design synthesis, D-011/D-012/D-013/D-004, the kill-history
schema doc vs. the actual recording path, `estimator.lua`/`driver.lua`/`rhythms.lua`/`history.lua`/`core.lua`,
the `.toc`, `tools/build.sh`, `.pkgmeta`, engineering principles, and a full source grep for open-item markers.

**The one fact that colours everything:** *nothing in this addon has been verified in a running WoW client
since the estimator overhaul began.* The 41-profile rhythm library (0.9.45's entire headline) and the driver
code that injects it were merged with in-game verification **explicitly deferred by the human**. Per
engineering principle 2.4, a green `pnpm validate` proves lint/format/logic under a Lua 5.1 host — it does
**not** prove the addon loads, that the `.toc` Interface matches, or that a single frame renders.

## Tier 1 — MUST-fix for 1.0.0 (genuine blockers to leaving alpha)

1. **The deferred in-game `/reload` — the whole rhythm library is unverified live.** (M) The
   rhythm-injection path and all 41 profiles have never run in-game. "Out of alpha" cannot honestly mean
   "we never loaded it." One Anniversary MC/BWL/AQ session must confirm: the addon loads, `ENCOUNTER_START`
   fires and supplies an id, a boss target upgrades to its rhythm, and the bar tracks. Top blocker; gates
   several items below.
2. **The `663` vs `150663` encounter id-space is unresolved.** (S, folded into #1) `rhythms.lua` dual-keys
   both precisely because it's unknown which the live client fires. The dual-alias **functionally hedges**,
   so it isn't independently correctness-breaking — but which reality is true is only knowable from the
   `/reload`, and the dead alias should eventually be trimmed.
3. **The kill-history recording does NOT implement the D-012 "locked" schema.** (L) The sharpest
   documented-vs-actual gap. D-012 + `kill-history-schema.md` define `db.global.history = { encounter =
   {[encounterID]=…}, creature = {[creatureID]=…} }` holding per-kill records (`name, level, dur, size,
   comp, diff, src, when`, 50-cap). But the actual recording writes the **old WO-025 shape**:
   `history.lua` stores `store[level][key] = { n, rate }` (a running mean); `driver.lua:288` calls it;
   `core.lua:96` inits `history = {}`. No `encounter`/`creature` split, no per-kill records, no
   `comp`/`size`/`diff`/`when`/`src`, no migration. D-012's whole stated reason to lock before 1.0 is
   *"so local recording is forward-compatible from day one"* — as written, a 1.0 user's recorded kills are
   in a collapsed running-mean shape that can never blend with a future WCL import. **Either** migrate
   recording to the D-012 shape now (rewrite `history.lua` + the driver record/prior path + a migration,
   new specs) **or** the human consciously accepts shipping the non-forward-compatible shape and wiping
   history when the importer lands. A MUST or an explicit, recorded waiver.
4. **Confirm the `.toc` Interface number against the live client.** (S, folded into #1) `## Interface:
   11509` carries a self-flagged NOTE to confirm via `/run print(select(4, GetBuildInfo()))`. Low
   functional risk; resolve during #1.

## Tier 2 — SHOULD for 1.0.0 (strongly desired, not a hard block)

5. **Buff-active detection matches auras by NAME, not spellID.** (M) `driver.lua` `readStates` matches
   `UnitAura` names against `nameIndex` — self-described "heuristic." Fragile to localized names/rank
   suffixes/collisions, and it's the signal that flips a utility bar to "fired/draining" (core UX).
   Degrades gracefully (a miss just doesn't show "active"). Downgrade to MUST if the `/reload` shows
   utility bars mis-signaling.
6. **The regime-aware confidence + freeze layer (WO-069 Phase 1) is design-only.** (L) D-014 Proposed;
   PR1–3 unstarted. The gate-heavy bosses (Rajaxx wave gate, C'Thun P1, Majordomo, Viscidus plateau) can
   still surface confident-wrong TTK; the shipped "rough" profiles give visibly wrong bars there. **But**
   the catastrophe that motivated D-013 (Lucifron 1.00 conf at 99% HP) was a CSV artifact, not a live bug
   — the existing sticky gate already hides the bar ~5s and shows at 0.72. So whether the regime layer
   *gates* 1.0 or lands in 1.1 is a genuine **product call**: 1.0 can defensibly ship on the rhythm library
   + the existing confidence gate, deferring the structural-tail bosses. Recommend the human decide after
   the #1 `/reload` reveals whether the gate bosses actually misbehave live. If deferred, record it.
7. **`tools/build.sh` is not reproducible on this host** (bash 3.2 vs BigWigs packager ≥4.3). (S) The two
   existing zips were hand-assembled. For a repeatable 1.0 release, `brew install bash` (4.3+) or document
   the requirement. Not a hard block (the human does the upload), but release reproducibility is a fair 1.0
   bar.
8. **Record D-014 and fix the stale "Next id."** (S) `Next id: D-013-IJ` is stale. D-014 anchors the
   regime design. Docs are direct-to-`main`; cheap.

## Tier 3 — Explicitly deferrable past 1.0.0

- **WCL import + external converter (D-012 piece 2)** — D-012 itself defers the importer; only the record
  *shape* (item #3) was ever pre-1.0.
- **The CLEU off-target tier (regime §4 PR4 / WO-072):** heal add-back, add-counters, Twin second-pool,
  Chromaggus vulnerability — physically health-invisible; needs combat-log plumbing. Confidence-capping
  holds the line.
- **Naxxramas + Onyxia profiles** — no Fresh-window corpus exists (probed).
- **Party (5-man) regime** — no 5-man corpus; routing already falls back to the pure chunk-clock.
- **TBC both-flavor build machinery (D-004 Model 2)** — deferred until a both-flavor addon exists.
- **Icon `refine` / per-encounter damage-taken hook** — prepared seams, not user-visible gaps.

## Verdict — is 1.0.0 close?

**Closer than the tier list looks, but not honestly there yet, and the gap is verification, not code.** The
engine is mature and heavily spec-covered; the rhythm library is a real, validated win. Two things genuinely
stand between 0.9.45 and "out of alpha," neither large: **(a)** the never-done in-game `/reload` (#1/#2/#4)
— one Anniversary session confirming load, id-space, and tracking, the line principle 2.4 draws between
"should work" and "confirmed"; and **(b)** a decision on the kill-history schema (#3), where the code
demonstrably does not write the schema D-012 declared "locked," so 1.0 must migrate or record a waiver.
Everything else is product judgment: the regime layer (#6) is designed but unbuilt, and 1.0 can defensibly
ship on the rhythm library + existing gate, pushing the structural tail to 1.1 — but that should be a
*chosen, recorded* decision. Net: no deep engineering remains for a minimal honest 1.0 — a `/reload`, a
schema decision, and a build tidy — but per D-011 the version bump is the human's call, and shouldn't happen
until item #1 turns "unverified" into "confirmed."
